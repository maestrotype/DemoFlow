04_TASK_MANAGEMENT — Как работать с задачами (для LLM)
Версия: 1.0.0
Для: Qwen3-Coder-30B и разработчика
Цель: Разбивать сложные задачи на маленькие подзадачи, чтобы модель не теряла контекст.

Основной подход

Из-за ограниченного контекста (32k токенов) все большие задачи делим на подзадачи максимум по 1–2 файла/компонента за раз.

Формат постановки задачи

Задача: [Название]
Приоритет: P0 / P1 / P2
Зависимости: (какие документы/файлы нужно прочитать)
Цель:
Короткое описание что должно получиться.
Что нужно сделать:

Подзадача 1
Подзадача 2
...

Файлы для изменения:

path/to/file1.ts
path/to/file2.html

Требования:

Использовать Design Tokens
Следовать Coding Standards
Сделать OnPush + Signals
...

Проверка после выполнения:

Что должно работать
Какие тесты/проверки провести


Приоритет задач (P0–P2)

P0 — Критично, блокирует дальнейшую разработку
P1 — Важно для MVP
P2 — Улучшения, полировка

Примеры разбиения (Editor)

Большая задача: Реализовать Scene Editor
Разбивается на:
P0:

Создать EditorLayout + базовый canvas container
Реализовать добавление/удаление Media Layer
Properties Panel (context-aware)
Простой Timeline + переключение сцен

P1:
5. Arrow Layer + drawing
6. Text Layer + inline editing
7. Drag & Drop + resize layers
8. Undo/Redo stack

Правила для LLM при выполнении задач
Сначала прочитай все необходимые документы (00_, 01_, 05_ и т.д.)
Предложи план из 3–6 подзадач перед началом кодирования
Делай одну подзадачу за раз
После выполнения покажи:
Изменённые файлы
Что теперь работает
Что нужно проверить дальше

Всегда следуй 03_CODING_STANDARDS.md
